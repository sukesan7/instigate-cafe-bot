# Instigate Cafe Bot — Agent engineering rules

This is a private-to-public modernization project for a stateful Discord bot. The Railway production service previously redeployed on GitHub pushes. **Never execute a live Discord connection, start `main.py`, run production pollers, edit Railway settings, publish a repository, or deploy without explicit owner consent.** Railway autodeploy must be disabled during modernization; disabling it does not stop an already active service.

Work on one small subtask at a time, from `START_HERE.md` and `phase_XX` prompts. No unauthorized `git push`, `git commit`, `git merge`, `git rebase`, history rewriting, branch deletion or GitHub visibility changes. Inspect the current source tree (the historical archive may be stale). Do not infer tests pass from a syntax check. Test offline using fake Discord interactions and mocked providers. Real private SQLite rows, lore, credentials, messages, resumes, and production data must never enter source, fixtures, logs or issue reports. No automatic provider calls during tests or imports. Do not remove apparently dead modules without verifying dynamic command registration and other entrypoints.

Before any edit: state existing behavior, exact files touched, risks, and tests. After edits: list changes, test commands and actual results, security/deployment impact, diff, proposed commit, GO/NO-GO and blockers. Stop after the assigned prompt. For schema changes, use synthetic fixtures and reversible migrations; for money/economy changes, assert atomicity and no duplicate settlement. For Git publication, inspect all history and obtain explicit owner approval separately from permission to run a public bot.
