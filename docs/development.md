## 1. Python Support Matrix & Packaging (`uv`)

| Python Version | Metadata (`pyproject.toml`) | Offline CI Matrix | Notes |
| :--- | :--- | :--- | :--- |
| `< 3.11` | Unsupported (`>=3.11,<3.14`) | Not run | Runtime imports Python 3.11+ `datetime.UTC`; `requires-python = ">=3.11,<3.14"` rejects Python 3.10 and earlier at install time. |
| `3.11` | Supported | Tested | Matches Ruff `target-version = "py311"`. |
| `3.12` | **Recommended Managed Default** | Tested | Matches `[tool.mypy] python_version = "3.12"` and container runtime (`Dockerfile`). |
| `3.13` | Supported | Tested | Uses `audioop-lts>=0.2.2; python_version >= '3.13'` because stdlib `audioop` was removed in 3.13. |
| `3.14+` | Excluded (`<3.14`) | Not run | Rolling distros (e.g. Arch/Garuda) may ship `/usr/bin/python3` as `3.14.x`; use `uv venv --python 3.12` rather than host Python 3.14. |

### Packaging Files (Single Authoritative Source)
- [`pyproject.toml`](../pyproject.toml) — **Single authoritative declaration** of runtime dependencies, `[dependency-groups] dev`, Pytest, Coverage, Ruff, and Mypy rules (`[tool.uv] package = false`).
- [`uv.lock`](../uv.lock) — Cross-platform locked dependency graph verified via `uv lock --check`.
- [`requirements.lock`](../requirements.lock) — **Autogenerated** hash-pinned runtime export (`uv export --frozen --no-dev --no-emit-project -o requirements.lock`) for `pip-audit` and `pip install --require-hashes`.
- [`requirements.txt`](../requirements.txt) — **Autogenerated** pip-compatible runtime export (`uv export --frozen --no-dev --no-hashes --no-emit-project -o requirements.txt`). Never hand-edit `requirements.txt` or `requirements.lock`.

### Local Environment Provisioning
```bash
# Canonical setup (recommended managed Python 3.12)
uv venv --python 3.12
uv sync --frozen --dev

# Install offline local pre-commit hooks
uv run pre-commit install

# Fallback pip-only runtime installation (from generated export)
python3.12 -m venv .venv
.venv/bin/pip install -r requirements.txt

# After editing dependencies in pyproject.toml (requires PyPI access):
uv lock
make export-requirements
```

## 2. Operational Safety Tiers (`Makefile`)

Developer commands in [`Makefile`](../Makefile) enforce explicit offline overrides (`DISCORD_TOKEN=""`, `ICBOT_ALLOW_GATEWAY="false"`, `LLM_ENABLED="false"`, `MARKET_WATCH_ENABLED="false"`, `BTC_WATCH_ENABLED="false"`, `JOBS_POLL_SECONDS="0"`):

| Safety Tier | Commands | Network / Side-Effect Boundary |
| :--- | :--- | :--- |
| **Tier 1: Static Only** | `uv run ruff check .`<br>`uv run ruff format --check .`<br>`uv run mypy .`<br>`uv run python tools/check_syntax.py`<br>`uv run python tools/check_docs.py` | Zero runtime execution, zero network calls, zero database mutations. |
| **Tier 2: Offline Runtime** | `uv run pytest`<br>`uv run python tools/smoke_offline.py`<br>`uv run python tools/smoke_staging.py`<br>`uv run python tools/scan_secrets.py --enforce-clean` | Synthetic temp SQLite databases, fake Discord interactions, mocked HTTP routers, and hard-blocked outbound IPv4/IPv6 sockets. |
| **Tier 3: Package Metadata Only** | `uv lock --check`<br>`uv run pip-audit --desc auto` | Contacts PyPI / OSV advisory metadata only. Never contacts Discord, Railway, or bot API providers. |
| **Tier 4: Live / Restricted** | `uv run python main.py --allow-gateway`<br>`uv run python scripts/admin/purge_global_commands.py --execute ...`<br>`git push` to deploy branches | Never executed in CI, pre-commit, or automated tests. Requires explicit human operator action (`purge_global_commands.py` defaults to `--dry-run`). |

## 3. Local Pre-Commit & GitHub Actions CI

### 3.1 Offline Pre-Commit Hooks ([`.pre-commit-config.yaml`](../.pre-commit-config.yaml))
All hooks use `repo: local` so they run 100% offline with pinned `.venv` binaries:
- `block-forbidden-files`: Blocks staging `.env*` (except `.env.example`), `*.db` / `-wal` / `-shm`, `*.sqlite*`, private keys (`*.pem`, `*.key`, `id_rsa*`, `id_ed25519*`), and private `lore.*.json` files.
- `scan-secrets-and-hygiene`: Executes `tools/scan_secrets.py --enforce-clean`.
- `block-private-key-blocks` & `check-merge-conflicts`: Rejects PEM headers and unresolved Git conflict markers.
- `check-syntax-ast-json-toml-yaml`: Executes `tools/check_syntax.py`.
- Ruff lint and format checks.

### 3.2 GitHub Actions Workflows
- **[`.github/workflows/ci.yml`](../.github/workflows/ci.yml) (Quality & Security Gate):** Runs on push to `main`, PRs, and manual dispatch with least-privilege `contents: read` permissions and zero live tokens or secrets. Splits deterministic offline checks (`quality` matrix across Python `3.11`, `3.12`, and `3.13`: `uv lock --check`, `scan_secrets.py --enforce-clean`, `pre-commit`, `ruff check`, `ruff format --check`, `mypy`, `smoke_offline.py`, `smoke_staging.py`, doc/command parity, usability audit tests, and full `pytest` branch coverage) from the separate networked PyPI/OSV advisory check (`dependency-audit`: `pip-audit --desc auto`). Contains zero deploy steps.
- **[`.github/workflows/live-smoke.yml`](../.github/workflows/live-smoke.yml) (Optional Live Provider Smoke):** Manual `workflow_dispatch`-only (no `schedule`, never triggers on pull requests); remains inert unless BOTH `confirm_live_network: true` and repository secret `OPT_IN_LIVE_SMOKE=true` are set, and enforces `DISCORD_TOKEN=""`, `GEMINI_API_KEY=""`, `ICBOT_ALLOW_GATEWAY=false`, `DB_PATH=":memory:"`.
- **[`.github/dependabot.yml`](../.github/dependabot.yml):** Weekly dependency update checks for `pip` and `github-actions`.

## 4. Full Pre-PR Verification Sequence

Run the single-command offline verifier before opening a pull request (never rely on syntax checks alone):

```bash
uv run python tools/verify_offline.py
# Or fast static-only mode while iterating:
uv run python tools/verify_offline.py --fast
```

### 4.1 Maintainer Engineering Invariants
- **Schema migrations:** Test every schema change against synthetic temporary SQLite databases with a backward-compatible upgrade path and verified backup/restore (`tools/backup_db.py`); never silently migrate live databases.
- **Economy & ledger atomicity:** Changes touching virtual balances, casino games, or ICSE trades must assert `BEGIN IMMEDIATE` atomicity and no duplicate settlement under concurrency.
- **Dynamic registration checks:** Before removing an apparently unused module, verify dynamic `/ic` command registration in [`icbot/registry.py`](../icbot/registry.py), task specs in [`icbot/scheduler.py`](../icbot/scheduler.py), and CLI scripts under `tools/`.

### 4.2 Tooling & Script Responsibilities (`tools/` vs. `scripts/`)
Each offline script serves a distinct purpose and is intentionally kept separate:
- `tools/smoke_offline.py` — Static AST parse across all Python files + zero-token, zero-network import & 53-command registration check (fast CI gate).
- `tools/smoke_staging.py` — Offline lifecycle check exercising SQLite Schema v7 WAL migrations, `ServiceContainer`, `TaskSupervisor`, and clean shutdown (also used inside offline Docker `--network none` verification).
- `tools/run_staging_acceptance.py` & `tools/verify_beta_readiness.py` — Synthetic fault-injection (27 scenarios) and 8-gate offline release-readiness harnesses imported by integration tests.
- `tools/run_usability_audit.py` — 4-archetype synthetic UX benchmark imported by unit tests.
- `tools/benchmark_db.py` & `tools/benchmark_profile.py` — Offline SQLite micro-benchmark and full-workload latency/memory profiler (`--json-out` writes to git-ignored `artifacts/`).
- `tools/backup_db.py`, `tools/scan_secrets.py`, `tools/check_docs.py`, `tools/check_command_docs.py`, `tools/check_syntax.py` — Operator backup/restore, secret hygiene, doc/command drift, and syntax utilities.
- `scripts/manual/probe_*.py` — Opt-in live network diagnostic probes (never collected by pytest; see [`scripts/manual/README.md`](../scripts/manual/README.md)).
- `scripts/admin/purge_global_commands.py` — Destructive Discord slash-command purge utility (defaults to `--dry-run`; see [`scripts/admin/README.md`](../scripts/admin/README.md)).

## 5. Secret Hygiene & Forbidden File Remediation

If `tools/scan_secrets.py --enforce-clean` flags an accidentally tracked database, private `.env` file, or private lore pack:

```bash
# Untrack without deleting your local file
git rm --cached data/dev.db data/dev.db-wal .env.local tools/lore.private.json

# Verify clean working tree and index
uv run python tools/scan_secrets.py --enforce-clean
```

If a real credential was committed, revoke and rotate it immediately at the provider console and follow [`SECURITY.md`](../SECURITY.md) and [Pre-Publication Security Remediation](deployment.md#91-pre-publication-security-and-history-remediation).
